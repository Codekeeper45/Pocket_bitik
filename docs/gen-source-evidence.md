# Проверка источника по реплике

`/gen` различает подпись Telegram-сообщения и реплику внутри картинки. Похожая подпись помогает найти кандидата, но не подтверждает нужную реплику.

## Runtime

- `gen_reference_evidence.py` семантически извлекает тип критерия и дословную фразу из запроса. Добавление текста на новую картинку не равно поиску источника.
- `_gen_source_preflight` проверяет реальные пиксели имеющихся кандидатов. При отсутствии совпадения выполняет поиск по одной фразе в существующем image embedding space, а не по всей сцене.
- До 48 retrieval hits дедуплицируются по Telegram media ID, скачиваются до 8 уникальных изображений. Число пиксельных проверок и время ограничены.
- Стикер предпочтительнее скриншота с той же репликой. Подтвержденный источник сохраняется при составлении промпта и remap.
- Если обязательный источник не подтвержден, запрос останавливается до image API и просит ссылку или изображение. Ошибка vision не превращается в подтверждение.
- Для приложенного источника конфликт с репликой требует уточнения, а не скрытой замены.
- Caption и image_text отдельно обозначены в каталоге. Диагностика содержит IDs, digest и verdict, без полного запроса и изображений. Локальный JSONL ограничен размером, права 600, не хранится в Git.

## Ограничения

Первая реализация извлекает один критерий реплики на запрос. Подтвержденный источник обязателен; остальные выбранные референсы проходят отдельное распределение ролей: другой персонаж, стиль или фон. Альтернативная внешность того же персонажа и неоднозначные источники исключаются. Явно приложенные изображения остаются в inputs. Для сложных запросов с несколькими разными репликами лучше передать конкретные источники; полноценный multi-criterion resolver требует отдельной доработки.

Поиск зависит от доступности текущего embedding API. Полная OCR-переиндексация базы не выполняется. Если нужный источник отсутствует в ограниченной выдаче, бот уточняет, а не выдумывает персонажа.

Новая проверка не запрещает фурри и не закрепляет имя за определенным стикерпаком. `-raw` сохраняет буквальный режим одиночной генерации. Пакетные и многостраничные запросы получают preflight перед запуском генерации.

## Проверки

`python -m pytest tests/test_gen_reference_disambiguation.py -q`

`python -m pytest tests -q`

Отдельно необходимы live positive/negative replay, реальный поиск без заранее заданного ID и нейтральная генерация с визуальным сравнением. Приватные трассы и медиа хранятся только в `qa-zaya-investigation/`, исключенном из Git.
